Day 3 — Fix a Broken uv Lockfile Specification

Completed November 14, 2026

The xFusionCorp ML team uses uv + lockfiles for consistent dependencies. The fraud-detection project's requirements.in broke team standards in three places.

Step by step:

  1. Diagnose the three faults: sklearn is the wrong name (the real package is scikit-learn); mlflow>=100.0 is an unsatisfiable pin (real versions are 2.x/3.x); pandas is missing entirely.
  2. Rewrite requirements.in with exactly the four top-level packages as bare names: scikit-learn, mlflow, pandas, numpy.
  3. Compile the lockfile: uv pip compile requirements.in -o requirements.txt — resolved pins include mlflow 3.18.0, numpy 2.5.4, pandas 3.1.1, scikit-learn 1.9.1, plus the full transitive tree.

What it taught: requirements.in is the human list — what the project intends to use. The lockfile is the frozen receipt — every package at an exact version, so any machine installs the identical environment and the model behaves the same everywhere.

Day 4 — Add a .gitignore and Untrack Committed Artifacts

Completed November 15, 2026

The fraud-detection repo was committed with no .gitignore, so .env, notebook checkpoints, a trained model file, __pycache__ output, and the venv were all tracked by Git.

Step by step:

  1. Read what's tracked: git ls-files.
  2. Write .gitignore with the six standard patterns: __pycache__/, *.pyc, venv/, .ipynb_checkpoints/, *.pkl, .env.
  3. Untrack the five artifacts with git rm --cached (with -r for directories) — the files stay on disk.
  4. Verify with git status: staged deletions listed, and the removed files do not reappear as untracked — the ignore rules are working.
  5. Commit the cleanup. Final git ls-files shows exactly .gitignore, README.md, requirements.txt, and the two source files.

What it taught: A .gitignore never untracks files Git already tracks — ignoring and untracking are two separate steps. git rm --cached removes a file from tracking while leaving it on disk.

Day 5 — Fix a Broken ML Workflow Makefile

Completed November 16, 2026

Fix the fraud-detection Makefile so make all completes, with six targets (setup/data/train/test/clean/all) aligned to team standards. Passed with about 20 seconds left on the lab timer.

Step by step:

  1. Diagnose with cat -T: the data recipe is indented with spaces, not a tab — Make's "missing separator" error.
  2. Fix the indentation with sed, swapping the leading spaces for a real tab.
  3. Spot that all: reads setup train test — the data target is missing; add it in its pipeline slot.
  4. Rebuild the clean target as three find-based lines: remove __pycache__ directories, remove .pytest_cache directories, and clear the contents of models/ while keeping the folder (-mindepth 1).
  5. Add the missing declaration at the top: .PHONY: setup data train test clean all.
  6. Run make all — completes; the lab check passes.

What it taught: A target's recipe lines must start with a real tab. A target line like all: setup data train test is a dependency list Make runs left to right — the order is the pipeline. .PHONY declares names as actions, not files, so Make never mistakes them for up-to-date files.

Day 6 — Fix a Broken Ruff and Black Configuration

Completed November 18, 2026

The fraud-detection project was failing both quality gates. Required end state: ruff and black both configured to line length 120, ruff's rule selection to include E, F, W, I, and both checks exiting 0.

Step by step:

  1. First runs from the wrong directory return path errors (E902, "Path 'src/' does not exist") — a location problem, not a code problem. From the project directory, the real faults show.
  2. Fix the config in pyproject.toml: ruff line-length 88 → 120; black line-length 100 → 120; ruff lint.select ["E", "F"] → ["E", "F", "W", "I"]; restructure ruff's deprecated top-level select into lint.select.
  3. The wider rule set surfaces two source findings in process_data.py: an unused os import (F401) and an unsorted import block (I001).
  4. Run ruff check src/ --fix: removing the unused import dissolves both findings — a one-import block can't be unsorted.
  5. Run black src/ to reformat the one flagged file.
  6. Verify the pair together: ruff check src/ → "All checks passed!"; black --check src/ → "5 files would be left unchanged." Both gates exit 0.

What it taught: Config before source: the settings decide what the tools judge at all. --check only reports — dropping it is what makes the tool write the fix. More rules can mean more errors, and that's coverage, not regression.

Day 7 — Test and Package the Fraud-Detection Module

Completed November 22, 2026

Write unit tests for the fraud-detection module's predict(), rectify the draft pyproject.toml, and build a compliant wheel.

Step by step:

  1. Read the source first: predict(data) returns a list of labels — [1 if row[0] > 100 else 0 for row in data] — so one fraud row in gives [1] back, not 1.
  2. Write tests/test_predict.py: the fraud test asserts predict([[150]]) == [1]; the legit test asserts predict([[50]]) == [0].
  3. Fix pyproject.toml in place: name fraud-detection → fraud_detection (underscore); version 0.0.1 → 0.1.0; dependencies [] → [scikit-learn, pandas, numpy]; pytest pythonpath set to ["src"] so the tests can find the package.
  4. Build with python3 -m build → dist/fraud_detection-0.1.0-py3-none-any.whl.
  5. Verify the artifact itself: the wheel's METADATA lists all three Requires-Dist entries, and pytest reports 2 passed.

What it taught: Edit config values in place, in their section — appending a second copy under a later header makes it that section's key and it does nothing. And verify the artifact, not the announcement: the wheel's filename can look right while the config inside is wrong.

Day 8 — Fix a Broken pre-commit Configuration

Completed November 24, 2026

Repair the draft .pre-commit-config.yaml so all five required hooks (trailing-whitespace, end-of-file-fixer, check-yaml, ruff, black) run clean, every repo pinned to a current release, hooks registered with git.

Step by step:

  1. First run stops at a structural error: the black entry has no rev: at all — config validation reports one error at a time, so the other defects hide behind it.
  2. Hand-add black's pin, sourced from black --version (26.5.1) — autoupdate can't fix a config it can't parse.
  3. Run pre-commit autoupdate: its failure messages double as diagnostics, naming the two bad hook ids exactly — check_yaml (should be check-yaml) and ruff-lint (should be ruff).
  4. Fix both ids, and point ruff at its current home, astral-sh/ruff-pre-commit (the draft used the old charliermarsh address).
  5. Autoupdate completes: pre-commit-hooks v2.3.0 → v6.0.0, ruff v0.1.0 → v0.17.6, black 26.5.1 → 26.10.1.
  6. Register the hooks: pre-commit install.
  7. Final run: pre-commit run --all-files — all five hooks Passed.

What it taught: Parse errors mask everything else — fix config in layers: structure, then ids and sources, then pins, then run. autoupdate refreshes pins only, but its "missing hooks" complaints tell you your id is wrong.
